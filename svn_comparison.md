# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это указатель на коммит: файл из 40 символов в каталоге
`.git/refs`. Создание ветки не копирует данные, занимает миллисекунды
и не требует сети. В SVN ветка — копия каталога внутри репозитория
(`svn copy`), которая создаётся на центральном сервере; слияние таких
копий исторически выполнялось вручную, с потерей информации о том,
что уже сливалось. Поэтому в SVN ветки заводили редко, а в Git —
под каждую задачу.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нельзя. SVN — централизованная система: история хранится только
на сервере, а `svn commit` отправляет изменения непосредственно в него.
Без связи с сервером можно лишь редактировать файлы в рабочей копии.
В Git репозиторий целиком лежит на локальной машине, поэтому коммиты,
ветки, слияния и просмотр истории доступны офлайн, а сеть нужна только
для обмена с удалённым репозиторием.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Legacy-проекты, где инфраструктура, скрипты и процессы уже построены
  вокруг SVN — миграция дороже поддержки.
- Репозитории с большими бинарными файлами и частичной выгрузкой:
  SVN позволяет забрать только нужный подкаталог, а Git тянет всю историю.
- Строгий централизованный контроль доступа с правами на отдельные
  каталоги и блокировка файлов (`svn lock`) для форматов, которые нельзя
  сливать, например CAD-чертежей.

Такие требования характерны для госсектора и банков.
